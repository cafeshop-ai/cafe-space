## Launch and observation rules

- Invoke the absolute Node executable directly with the canonical CLI path, not a shell or Windows `.cmd` shim. Match v0's `--mode rpc --offline --no-extensions --no-approve --no-themes --session-dir ... --session-id ...`. No v0 collaboration extension, room tokens or ambient API keys are forwarded. M3 is out of scope.
- Host must provide an owner-only session directory, private native ID and the approved cwd identity, and own the resulting process. Resume validates the native ID/cwd/header and selects the exact native history file with `--session <canonical-file>`, not `--session-id` (which can create a missing conversation). It retains the same private ID/storage directory; missing identity/history is an error, never a new conversation disguised as Resume. No automatic replay or `--continue`.
- Startup is confirmed by a correlated `get_state` response with the expected private native ID and idle flags. The startup query is not a prompt; unexpected pre-prompt activity fails `PI_STARTUP_BUSY` rather than inventing a ready transition or accepting a different conversation. Once a run starts, only `agent_settled` is ready; `agent_end`, successful prompt responses and idle-looking intermediate queries do not complete a run. A `handled` prompt starts no run. This distinguishes initial readiness from run completion, because Pi emits no startup `agent_settled`.
- Consume strict LF-framed JSON objects continuously, accept CRLF, preserve U+2028/U+2029 and UTF-8 across read boundaries, and reject malformed bounded JSON or incomplete EOF with fixed codes. Oversized records are discarded through LF with a byte-counted placeholder; unknown/image blocks are represented by byte-counted placeholders. Assembled display overflow is explicitly truncated, not a session failure. Commands and dialogs remain bounded. Drain stderr separately without treating it as protocol or sharing raw diagnostics.
- Correlate responses by unique ID and command, not order. A successful prompt/steer/follow-up response is acceptance, not completion. A failed response is rejected with a fixed code, never the raw runtime error. EOF, write failure or a deadline leaves an unacknowledged command unknown; never retry automatically. Host owns deadlines, I/O scheduling, fences and caller/run ownership checks.
- A `confirm` dialog maps to explicit Allow once / Deny. Pi has no built-in tool-policy approval: do not infer permission semantics from arbitrary option labels. Generic `select`, `input` and `editor` require `waiting_for_local_ui`; the current v2 approval decision cannot carry free-form values. The `--no-extensions --no-approve` profile runs tools without asking. M1-6 must show “Runs tools without asking”, not a false approval toggle; `approval_for_session` is false. An oversized confirm request requires local UI rather than offering approval with hidden details. Writing an extension UI response is dispatched only, because Pi sends no acknowledgement.

## Current implementation

`crates/adapters/src/pi/` contains passive installation inspection, launch/resume preflight, bounded LF framing, correlated command outcomes, observed lifecycle, transcript/tool mapping and explicit confirmation dispatch. `test/fake-pi.mjs` runs through the daemon's actual native ownership code in `tests/managed.rs`, never through Pi. Rust and Web tests share the fixtures. Windows Node arguments use regular absolute paths after canonical validation because Node's entry-point resolver rejects verbatim `\\\\?\\` script paths. The Host-side `pi_driver::Driver` now provides bounded I/O workers over owned streams: an 8-record writer/event queue, 32-record nonblocking polls, a 30-second response/write deadline, fixed unknown outcomes with no replay, private stderr draining, and approval dispatch only after a complete write/flush. The native-only `Host::launch_pi_session` now attaches the driver and owned process atomically under admission. Startup readiness and failures reach durable session state and the bounded session event stream. Unexpected EOF/root exit maps to `failed(PI_CONNECTION_LOST)`; malformed records and deadlines retain their fixed failure codes. Host clears `activeRunId` and persists failure before its explicit process stop. A terminal-state guard prevents late readiness/OS-exit observations from replacing failure with `stopped`. Explicit close, shutdown and update detach the driver normally and remain stopped. POSIX supervisors release their own standard-stream descriptors after target spawn, so they do not conceal a target-only EOF. The shared `host-lifecycle.json` fixture is consumed by Rust and Web; the native EOF fixture closes stdout while keeping its process alive to require Host teardown. Schema v5 now commits the private native ID with session creation before spawn, uses owner-only `agent-sessions/pi-<native-id>` directories (lowercase IDs and a prefix avoid Windows aliases/device names), and stores normalized transcript observations before publishing message events. The cache preserves retained-message upsert order and caps each session at 128 messages / 128 KiB encoded JSON; eviction or an omitted record sets `historyTruncated`. Failure and restart atomically mark unfinished cached displays incomplete, without inferring execution outcomes; terminal sessions ignore late messages. Native history is not rewritten. Private identity lookup rejects missing/mismatched Resume metadata and concurrent conversation ownership. The native-only `Host::start_installed_pi` factory now obtains that identity from durable storage, validates the source lifecycle/project/cwd, requires exactly one matching regular owned native history file, and uses the existing version-3 header preflight before passing its canonical path as `--session`. Missing, ambiguous, aliased, insecure or mismatched files fail before target creation/spawn; no new-history fallback is permitted. Native-only prompt/control command routing is described below. Native Host confirmation routing is described below. The native Host Resume path has offline integration coverage and the local restricted-tools diagnostic below. Bounded current-context Resume display hydration is described below; complete native archive paging, explicit shell import and production admission remain open. The local-only owner settings wire implementation below is pending same-SHA CI and non-author review. Native owner persistence and structural PATH admission are described below. No production runtime or authentication probe is enabled.

### Native Host command routing (production disabled)

`Host::command_pi` is a local-owner Rust entry. The full v5 API now admits only `set_model`/`set_thinking` through its asynchronous receiver; prompt/cancel/approval wire routing remains disabled. It validates the shared request codec, session/stream/cwd generations and approved directory identity before enqueue, returns a receiver for the correlated native outcome, and never treats an enqueue, writer completion or `agent_start` as command acceptance. Public operation/run IDs are random and independent of private native request IDs. Native startup enables the implemented Pi controls without inferring `toolApproval` from a runtime ID. Initial model metadata comes only from validated native state; model/thinking mutations require a subsequent correlated `get_state` readback before an applied result, preserving effective values even when native Pi clamps a requested level. Failed or missing readback is unknown, not rejection of the already-applied mutation.

First prompts are reserved against duplicate submission while awaiting native activity. Observed run start persists `activeRunId`; only observed settlement clears it as ready. Unowned activity fails closed. Active input maps to steer/follow-up with reordered replies independently correlated. Cancellation checks the owned run, awaits `clear_queue`, rechecks the current run and observed driver state, then sends `abort`; input remains blocked throughout the cancellation chain. Observations in each poll are persisted before command outcomes advance cancellation, so a run already observed settled is not aborted. Abort acknowledgement is dispatched, not turn completion. For a cancel request, `applied(empty)` specifically means `clear_queue` was acknowledged and the target run was already observed settled, so this request sent no abort; it must not be presented as proof that the request interrupted the run. `dispatched` means abort was acknowledged, with observed settlement still authoritative. `Ready` alone does not establish why a run ended. Host publishes the observed session state before resolving the command receiver, but this is not a transport-arrival guarantee: before M1-6 wire admission, test both response/event arrival orders and reconcile authoritative state without inferring cancellation causality from either. Model/thinking controls likewise display the read-back effective values, not the originally requested values. This uses the existing result kinds without a new protocol payload; richer per-request notices remain a separate protocol decision. Disconnect, malformed input, timeout and explicit close leave unacknowledged commands unknown without replay. An accepted prompt without any subsequent lifecycle event remains reserved until settlement or explicit close; no completion is invented.

The shared `host-commands.json` fixture drives owned fake-process cases for initial configuration, first/handled turns, reordered input acknowledgements, cancel/settlement races, stale run/stream/cwd fences, remote denial, effective model/thinking readback and rejected/missing readback, start without acknowledgement, duplicate reservation, failures and close with pending input. These are native Rust integration checks with zero model calls. The local full-wire API admits configuration with the fixture-first `configuration-wire-v5.json` contract, and prompt/cancel use the command wire contract below. Approval wire dispatch still rejects controls and runtime listing remains empty; final-SHA multi-platform acceptance, historical display hydration and owner/PATH readiness remain open. No new real Pi authorization or schema migration is implied.

### Native Host confirmations (production disabled)

Confirmations use the same local/stream/cwd/directory fences as commands. Host generates public random approval IDs rather than exposing per-adapter IDs or native dialog IDs, and `get_session` includes the current bounded confirmations at its event high-water mark. `approval_required` is published only after the in-memory view is updated. Retained encoded confirmation data is capped at 64 KiB per session; a request that cannot be offered in full requires local UI rather than silently truncating safety-relevant details or approving them. The driver is moved to the same local-UI state. Other generic select/input/editor requests also require local UI. These dialogs do not change the profile's truthful `toolApproval=never_asks` or create per-tool permission policy.

A selected Allow once or Deny resolves its native-only receiver as `dispatched` only after complete writer flush, never merely after enqueue, and publishes `approval_resolved` with the real selected decision while the dialog is still open. Pi supplies no native acknowledgement. Duplicate pending selections and Allow for session are rejected before a second write. If settlement or failure closes the dialog before writer confirmation, a later complete-write observation can still report dispatched, but no fabricated decision event is added to the already-closed dialog. Unconfirmed writes remain unknown and are never replayed. Unselected dialogs closed by settlement, failure, explicit close or restart are simply absent from the authoritative snapshot; no Allow/Deny decision is invented. Claude's frontend reducer moves pending approvals to a bounded client-only expired list on authoritative ready/stopping/stopped/failed session changes; unanswered requests are shown as expired rather than silently disappearing, and sent replies are not mislabeled as unapproved. No approval state is resumed or executed after restart. Existing confirmation UI components are unchanged.

`host-approvals.json` pins the native Rust cases and is available for the separately owned Web checks. Owned fake-process tests cover Allow once/Deny, scope rejection, stale fences, cross-session and remote denial, duplicate writes, cancel/close/crash closure, generic local UI and escaped oversized confirmation data. Deterministic Host/Driver tests cover writer/settlement ordering, unknown write outcomes, event-capacity rollback, and snapshot/event identity. These are offline native Host tests, not wire approval or full Host Resume acceptance.

Pi 1.5.0 redacted thinking blocks may omit visible `thinking` text. The adapter displays a fixed `[Redacted thinking]` placeholder for `redacted=true`, even when a text field is present, and never exports the replay signature. Unredacted blocks still require text; malformed content is not silently hidden. The shared `display-limits.json` fixture and adapter regression cover missing text, hidden text/signatures and subsequent settlement.

Known display limits: records above 1 MiB are drained without retaining the payload; assembled messages stay within 64 KiB / 128 blocks, with explicit excerpts or omission markers. Images/unknown blocks show their encoded JSON byte count, never their opaque payload. A discarded record has unknown type: it never acknowledges a pending command or establishes readiness. A missing response remains unknown at its Host deadline; a missing settlement cannot be guessed. Incomplete active transcripts are marked as such without inventing an execution outcome, and orphaned deltas are skipped until a usable start/end boundary. Limits do not add attachments or pagination. Prompt acceptance is not turn completion; a run remains running until observed settlement or a connection failure.

Native CI now keeps the Apple Silicon jobs and additionally tests `macos-15-intel` in both workflows (base 5 jobs, Desktop 4). Repeated unassigned ARM runners are an external capacity failure, not a passing test. Intel results are separate native macOS evidence, not proof that Apple Silicon passed. The label is listed in [GitHub’s standard hosted-runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners#standard-github-hosted-runners-for-public-repositories); no larger/self-hosted runner is introduced.

### Native Host Resume factory (production disabled)

`Host::start_installed_pi` accepts a trusted installation and local access only; callers cannot supply a native ID or Resume file. New sessions receive a private random native identity. Resume reuses the persisted source identity only after the shared lifecycle and private-registry checks succeed in a rolled-back preflight transaction. Existing target IDs return their durable outcome without launching, revalidating/recreating history or replaying input. Raw argument-based `launch_pi_session` is now New-only; it cannot bypass the Resume factory.

Both private parent directories remain open through validation/spawn. Resume opens existing directories without creating them, scans at most 1,024 entries, and requires a unique exact `_<native-id>.jsonl` suffix. Final symlinks/reparse points, non-regular files and hard links are rejected. Windows checks owner-only ACLs. On Unix, native Pi's normal 0644 history files are allowed inside the held owner-only/no-ACL parents, but a different owner or group/other write access is rejected. The existing adapter preflight checks the canonical parent, native ID, v3 header and approved cwd. Identity readback still gates readiness; a writer completion is not acceptance.

The normalized display cache is **not** imported as native history. Resume now withholds startup `ready` until a correlated `get_messages` response has been projected and atomically stored. That RPC returns the runtime's current conversation; the adapter does not concatenate append-order JSONL branches or reuse the source display cache. System prompt/tool definitions, hidden/custom roles, signatures, provider metadata and tool details are not exported. User/assistant content and matched tool results use the existing bounded display mapper; image/unknown blocks remain placeholders, and redacted thinking remains opaque. At most 4,096 native messages are projected into the newest 128 displays / 128 KiB encoded JSON, within the existing 1 MiB framed-record bound. The same adapter counter allocates history and subsequent live IDs, preventing overwrites. Host keeps `historyTruncated=true` because this is current context, not a complete pre-compaction archive. Rejected/malformed/timed-out history fails startup with fixed codes and owned cleanup; it sends no prompt and never retries. A response exceeding the existing record bound is not treated as an acknowledgement or complete history. `fixtures/pi-rpc/history.json` precedes this implementation and pins privacy/ordering/bounds; `host-resume.json` drives 18 owned fake-process cases, including exact-file recall after Host reopen, stopped idempotent retry, stale stream rejection and fail-closed history/identity/cwd cases. Shared private-path and native-file unit checks cover missing paths, unsafe permissions, aliases and wrong path kinds. The synthetic Host fixture preallocates its empty history file with the shared private-file primitive, so elevated Windows CI does not substitute a default Administrators-owned file for the required current-user-owned fixture. Production checks are unchanged: an elevated runtime that creates history with a different owner is rejected; no ownership/ACL repair or fallback is performed. The local real-Pi diagnostic does not establish elevated-Windows support.

### Native owner environment (production disabled)

`Host::patch_owner_environment` and `owner_environment_status` remain local-owner Rust entries; the separate v4 projection above exposes only the narrower masked contract. A strict version-1 `owner-environment.json` in the private daemon root stores at most 64 KiB encoded JSON. This is a new optional private format; no existing SQLite record or wire shape changes.
