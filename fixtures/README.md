# Shared fixtures

- `pi-rpc/runtime-registration.json` pins full-wire v7 local-only registration/removal, private settings v1 and path-free summaries. Rust/TS codecs share the frames; owned fake Agent tests cover registration and New/Resume over real private IPC. A separate disposable-CI gate executes the actual CLI against the daemon without starting an Agent. These checks do not authorize or prove real-Agent acceptance.

- `session-activity/proposal.json` describes the #57 source contract pending native acceptance; `session-activity/wire-v6.json` contains current v7 examples (historical filename), not permission to migrate user data. Shared fixtures pin Unicode-scalar-safe 256-byte previews, source provenance (opaque blocks versus literal placeholders), monotonic/unknown clocks and sorting. Native `UserPreview` pairs message ID, session-local insertion order and nullable text with the display observation; absence is unknown and null text clears. The Host validates provenance and commits live/history metadata with the display transaction. Schema 6 stores summaries independently of the cache and retains per-message SHA-256 receipts so eviction does not turn identical replay into new activity; history never advances the clock. This is source implementation pending Rust execution. Creation/lifecycle/configuration timestamps, public snapshot fields and metadata-only events are implemented in the candidate; the full protocol is 7 and frozen control stays 2. This does not prove native acceptance. `web/test/session-activity-contract.test.ts` checks fixture consistency; `node --test test/session-activity-sql.test.mjs` exercises source-extracted SQL, not Rust or the Host. Schema upgrades from 5 and old-daemon refusal need separate native evidence.
- `cli/session.json` pins the existing-wire CLI command/fence mappings, Unicode text and outcome preservation. Native Rust parser, BOM decoder, shell/subprocess output checks and isolated IPC-client tests consume it. It introduces no protocol method or runnable Agent; Windows PowerShell 7 is required in CI and an absent local shell is reported as skipped.
- `v0-go/` pins the legacy v0/protocol-v1 baseline. Shared Go/TypeScript fixtures and specs are copied from the source revision; only uncovered room-identity/signature examples are newly recorded from Go. `v0-go/manifest.json` lists source paths and SHA-256 hashes. Do not hand-edit them.
- `v2/` contains draft daemon-local API examples, including the version handshake, event subscription/snapshot and operation outcomes. Rust tests decode/re-encode them; TypeScript checks the same JSON against bindings generated from Rust. `session-lifecycle.json` is an offline trace of independent event frames, not a wire batch; Rust and TS test its observed states, fences and fixed stopped reasons. `session-transitions.json` is the shared offline state-transition matrix; Rust tests all 49 state pairs, and TS checks the trace against the same matrix.
- `v2/migration-failed-health-response.json` and `v2/schema-migration-failed-response.json` cover readable health without handover readiness and fixed work rejection after a migration failure; the daemon API test consumes both on the same live connection.
- `v2/project-requests.json` and `v2/project-events.json` are offline independent-frame traces for local project administration and shared path-free events. `get-project-root-request.json` / `project-root-response.json` cover the local-only path read; `project-response.json`, `project-local-only.json` and `project-stale-fence.json` cover shared summaries and fixed rejections. Paths are synthetic and never used to approve a real project. These fixtures precede the M1-2 storage/CLI implementation.
- The `v2/` directory names the local API family; its full-API frames now carry `protocolVersion: 7`. `owner-environment.json` pins the local-only detected/configured masking and adopt/remove/set contract. Frozen control generation 2 is unchanged. `runtimes-response.json` and `session-tool-approval-event.json` exercise the required `toolApproval` field (`never_asks`, `may_ask`, `unknown`) on profiles and actual session capabilities. Rust and TypeScript consume both. Missing fields are errors, not an inferred permission policy.
- `control-v2/trace.json` freezes update-control generation 2 (architecture D18): the frames a native controller exchanges with any daemon to read status, prepare, poll, cancel and shut down. Frames marked `appliesWhen` describe the control-only rejection once a daemon's full protocol is newer than 2. Never edit this file; a new control generation gets its own directory. `crates/protocol/tests/control_v2.rs` checks all 14 frames for codec round trips, request/response pairing, conditional metadata, unknown-field rejection and version rejection. These are wire-shape checks only; they do not prove daemon-side `CONTROL_ONLY` enforcement or a cross-version update.
- `migrations/m0-api.json` freezes the hello/list-sessions requests from pinned M0 `3953e33`. Only the legacy OS-registration probe uses them; they are not current full API or an extension of the control whitelist.
- `pi-rpc/model-list-wire-v5.json` pins current full-wire v7 fenced `list_models` and the bounded `models` result; the filename is historical, as are the other `*-v5.json` wire fixture paths. Rust contract tests and generated TypeScript share it; v4 and frozen control reject it. It preserves native rejected/unknown distinctions, empty-list semantics, local-owner admission and no automatic retry. Owned fake-process tests exercise asynchronous real local IPC, close/disconnect/timeout, late directory replacement and both response/event orders. No production runtime is enabled; UI/readback and final-head cross-platform gates remain separate.
- `pi-rpc/approvals-wire-v5.json` shares local-owner confirmation selections, truthful dispatched/rejected/unknown replies and public-ID events between Rust and generated TypeScript. Owned fake-process IPC tests cover decisions, unsupported scope, stale/remote/missing-ID and duplicate denial, cancel/close/disconnect, local UI and size limits. Tests read health without Host polling to reject enqueue-as-dispatch, then release synthetic settlement only after actual writer dispatch and its decision event. No native acknowledgement, per-tool policy or production Agent readiness is inferred.
- `pi-rpc/commands-wire-v5.json` pins existing prompt/steer/follow-up/cancel shapes, fences and dispatched/rejected/unknown/applied examples shared by Rust codecs and generated TypeScript. Owned fake-process local IPC tests exercise concurrent command replies (32 per connection, one reserved for cancel), reversed native acknowledgements, cancel while prompt acknowledgement is absent, health/events, stale/remote denial, timeout/close/disconnect and no replay. Native acceptance is not settlement, and cancel rechecks its owned run after acknowledged queue clearing. Runtime listing stays empty; real Agent launch, desktop chat and final-candidate cross-platform acceptance are not claimed.
- `pi-rpc/desktop-host-v5.json` pins a test-harness-only fake-Pi Host server: one isolated private IPC connection, a 60-second accept/serve deadline, no runtime admission or registration. Its default managed-harness self-check exercises initial snapshot, a completed normal turn, a held busy turn, same-run fenced cancellation, Allow once/Deny confirmation turns, authoritative Ready/stopped transcript readbacks and timeout cleanup. The external `--desktop-host-fixture` entry prints local runner metadata, serves one connection and reports native command names/count and synthetic confirmation booleans; success must exactly match `expectedNativeCommands`, proving four prompts, one ordered clear/abort, and one Allow once then Deny without replay. `desktop/scripts/host-probe.mjs` connects the opt-in debug WebView using the actual Channel/JS client and requires authoritative settled/closed transcript readback without replay. The server self-check alone is not a WebView test; neither entry is a production daemon/runtime option.
- `pi-rpc/update-gate.json` pins native busy/idle update admission: an idle owned Pi process is not an active turn; startup, unknown drivers, reserved prompts, unanswered confirmations on ready drivers and pending commands/model queries remain busy. Owned fake processes cover stop-before-marker, pending-lease disconnect, target-host confirmation via a synthetic controller in a temporary root, and explicit Resume without a prompt. No OS service, real Agent or wire runtime is enabled.
- `pi-rpc/host-lifecycle.json` distinguishes explicit close/update/shutdown from abnormal EOF, root exit, malformed RPC and deadline. Host lifecycle tests persist failure before explicit process cleanup and keep terminal states stable across late polls/restart; production runtime admission remains disabled.
- `pi-rpc/history.json` pins native-only, correlated `get_messages` Resume display hydration: current context, not append-order JSONL or the source display cache; hidden metadata never projected; bounded retained displays and non-colliding live IDs. Startup `ready` follows atomic cache initialization. `historyTruncated` stays true because current context can omit pre-compaction history. Owned fake-process rejection/invalid/timeout/bounds cases supplement `host-resume.json`; no real Agent or wire runtime is admitted.
- `pi-rpc/host-storage.json` shares cache bounds and the explicit interrupted-message display between Rust Host/storage tests and Web checks. The SQLite cache is a bounded projection, not a replacement for native history or evidence of full Host Resume.
- `migrations/v1.sql` is a synthetic M0 schema with sentinel data for migration/backup tests, not a captured user database. `v2.sql` is the published session schema; `v3.sql` adds project storage. `v3-session.json` freezes an old snapshot without tool approval. `v4.sql` inserts an explicit `"unknown"` into stored capabilities; Rust validates every rewritten snapshot before commit. `v5.sql` adds private native identity mappings and a bounded transcript projection. `v6.sql` adds durable activity metadata and per-message receipts without backfilling legacy activity. Candidate test source covers upgrades from 1 through 5 with one verified starting-version backup and all required steps/history rows in one transaction, including rollback on invalid records or table conflicts. The opt-in pinned v1–v5 binary matrix must reject schema 6 without changing either the database or its backup; this candidate still needs native execution evidence.

`process-ownership/windows-stop.json` pins query/confirmed/cancelled Windows session-end and unexpected-window-close behavior. Native Windows tests target only their own hidden top-level window, never broadcast or sign out the owner; they verify synchronous owned-child cleanup, duplicate-end idempotence and both durable terminal records. The separately opted-in hosted-runner autostart test also targets the verified current logon-task process with bounded query/cancel/confirmed-end messages and a held process-exit check. Neither probe performs or proves actual Windows logoff/shutdown.

`process-ownership/contract.json` defines offline native tree/handle/cwd cases; `pi-rpc/{contract,traces}.json` pins the external Pi 1.5.0 adapter boundary, synthetic lifecycle and command examples. These are not v2 wire batches. Rust adapter tests and Web fixture tests consume the Pi examples; `test/fake-pi.mjs` exercises the actual owned-process pipes without loading Pi or calling a model.

Legacy v0 device protocol v1 and local API v2 are separate contracts. Do not pass v0 device frames to the v2 decoder.
